Real rates from AWS's pricing page (aws.amazon.com/mediaconvert/pricing/): H.264 uses the Basic tier ($0.0075/min at SD). DCP prices compute at 1.000 ⊇ (one DCP credit) = $0.0003171 USD per 100 vCPU-seconds. "Raw DCP cost" is priced from each fleet slice's own real compute time, so it reflects whatever hardware actually ran it. Bell's internal fleet runs at roughly 38% the per-core speed of AWS's, so the same output can cost proportionally more real vCPU-seconds than a same-hardware comparison to AWS would suggest. Two numbers follow: run internally, Bell earns back 80% of its compute spend, netting about 1/5 (20%) of the raw DCP cost. Resold externally, Distributive keeps 20% of what the customer pays and Bell keeps the other 80% as revenue.

Same resolution, two encoders: H.264 vs. AV1

Two extra renditions ride along in every job, outside the real ABR ladder above: 320×240 via libopenh264 and via libsvtav1, both in each encoder's own quality mode (not a bitrate cap, which would make both converge to the same size regardless of efficiency). AV1 costs meaningfully more compute per encode; watch the size difference land as results come in. Neither is included in playback below: this pair exists purely for comparison, and MPEG-TS (this pipeline's segment container) isn't reliably supported for AV1 across hls.js/browsers.
